# Evidence handling and verification

`runs/` contains path-redacted sharing copies of the recorded evidence. Local account and workspace paths are replaced; synthetic tenant names, fixture identifiers and localhost addresses are retained because they explain the experiments. Passwords in the session experiment use REA secret references. Header values were not requested. Browser profiles, session stores, package caches and unrelated laptop data are excluded.

`provenance/redaction-map.json` lists the source relative path, original SHA-256 and distributed SHA-256 for each transformed file. `SHA256SUMS.json` records distributed files. A transformed copy is not the original raw artifact. Internal REA capture/graph digests are preserved as provenance and can refer to pre-redaction bytes; do not represent path-redacted envelopes as untouched authenticated imports. Generate a new run for strict end-to-end REA import/export provenance verification.

The verifier checks the distributed file hashes and retained body bytes where REA supplies a content digest. It also reads the actual scenario DOM and network records to check the claimed outcomes; convenience summaries alone are not accepted as proof.

Original baseline assertions: `runs/laptop-20261018-01/observations.csv`. Complete measured CLI calls: each run's `commands.jsonl`. Main browser evidence: `rea-evidence/*.json`. Supplemental direct HTTP records and regression outputs are labelled separately.

The historical studies preserve failures and limits: sandbox-denied initial tests, REA overall incomplete scenario coverage, unknown UI causality, the v1 public-token weakness, lack of blind reconstruction in those stages, and deployment limitations of the v2 local fixture. The later bounded-agent extension adds withheld-target prediction scores, with its own limits below.

The actual-agent extension under `runs/agent-20261019/` freezes source before target generation, commits targets by hash, and freezes every predictor before selecting common unobserved holdouts. It publishes projected agent/tool transcripts and actual REA captures; raw engine events, account notifications and private reasoning streams remain excluded. Model inference uses the configured Codex service with synthetic observations. `node agent-benchmark/verify.mjs` checks source and target hashes, every prediction, aggregate arithmetic, DOM projections, distinct linked network transactions and captured-body hashes. This is internal evidence consistency, not independent attestation of the operator, host or timestamps. See the scorecard for scope, effort, coverage and failures.

For the later workflow boundary extension, `runs/boundary-20261019/pre-run-freeze.json` pins its prospective plan and implementation. Its command log records portable command paths at creation; the six new REA capture files required no path rewriting. The new verifier checks 98 result rows against distinct network transactions, including method, route, request body, status and response body, and verifies 196 captured-body digests. All six captures retain overall incomplete status and `equality_eligible: false`. Application payload comparison canonicalises random job IDs and excludes timing, headers, transport and unobserved surfaces; it is not whole-capture equivalence. The exact-match bound was planned; its extension to predictions within 5% is a labelled post-hoc arithmetic check, not another attack run.

For the 19 October reconstruction extension, `provenance/reconstruction-redactions.json` records the two command-log path redactions. The new verifiers check frozen models, original source hashes, every scored prediction and matching browser network responses. The initial plan was frozen before execution; the approved-quote-only follow-up was chosen after seeing the initial results and reuses the original holdouts. Neither is claimed to be an independent blind AI red team. See `docs/RECONSTRUCTION_FINDINGS.md` for the measured scope and product trade-offs.

## Combined-defence records

The run in runs/combinations-20261019 freezes 84 checkpoint predictors from 42 agents. The first checkpoint hash appears before its continuation prompt. Targets are committed before observations; common holdouts exclude the successful observation union across both stages and all policies. The new verifier also replays expected policy decisions against captured rows, checks quote/export request bodies, re-scores both checkpoints, and checks 168 utility journeys. Its output records 340 operations, 3200 matched rows and 7080 body digests. A cumulative 192-stage token count is counted once. Raw engine events remain under ignored local output directories and are excluded from distribution. This is internal consistency verification, not independent attestation.

The combination study also retains two explicitly supplementary analyses added after its protocol freeze. memorisation.json replays already observed finite supported outputs without new requests; diagnostics.json checks each checkpoint against its actual stage-final transcript and records unchanged coefficients and initial batching. Neither changes the primary score, target set or frozen agent protocol. Both are recomputed by the offline verifier when present.
