# Continue the research without overstating it

The local hard-block and disclosure experiments are complete for the named cases. The [19 October reconstruction study](RECONSTRUCTION_FINDINGS.md) measures programmatic inference across 16 synthetic targets. The subsequent [workflow boundary study](BOUNDARY_FINDINGS.md) extends coverage to exports, jobs, replaced sessions and approval creation, with negative controls and a conditional indistinguishability demonstration. [How REA works](HOW_REA_WORKS.md) traces actual observation mechanisms to installed source. These stages do not complete the independent blind-agent work below. The next useful work is to challenge unknown rule families, realistic approvals and the remaining information surfaces.

1. **Independent reconstruction:** a separate white operator prepares a changed private rule and hidden holdout inputs. Give a fresh red session only an entitled browser and a fixed query/time budget. Do not give it this repository, source, paper, previous answers or pricing bands. Freeze its predictor before white-team scoring. Report exact match, absolute error, query count, elapsed time and failures on unseen inputs. Repeat across independent sessions and variants. The current study has no such score.
2. **Boundary expansion:** validate realistic exports, jobs and service identities beyond the new small fixture; add caches, support tools, role changes and revocation during an active subscription. Test whether approval creation or colluding accounts restore a general output oracle. The current event fixture is a finite response, not a long-lived subscription. The new job fixture checks tenant and approval at read time, but has no real distributed queue.
3. **Deployment validation:** replace fixture identity with the product's maintained authentication stack, use TLS and Secure cookies, durable shared policy and atomic quotas. Test races, replica inconsistency and dependency failure. Measure normal task completion and latency alongside denials.
4. **Adversarial assessment:** allow a fresh authorised tester to choose requests and adapt to results. Scripted probes provide reproducible cases but do not replace an adaptive review.

For every contribution, include the exact source revision, REA and browser versions, complete commands, sanitised captures, scope, assumptions, successful normal controls and unsuccessful attack attempts. Keep capture errors and missing coverage visible. Add an acceptance criterion and evidence path for each new protection claim.

Historical baseline `findings.md` and `contributions.md` describe that stage only. The root README, success criteria and expanded paper incorporate the later repetitions, partial-fix experiments and session lab. The original protocol is provenance, not evidence that every proposed hypothesis was tested.
